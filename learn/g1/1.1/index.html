1.1开工三件套

本节任务：初始化 Next.js 项目，写入协作铁规矩。

输入什么已确定的工具选题、目标用户、核心输入输出，以及可用的本地开发环境。
输出什么项目可运行、规则文件存在、首个 Git 提交完成。
学会什么用任务卡、AGENTS.md 和验收先行解决 Agent 跨会话失忆。
本节阅读方法
  1. 先读白话讲解
  2. 照着步骤动手做
  3. 逐条完成验收
  4. 遇到问题看常见坑
不要只看

代码块、提示词和检查框都是本节任务的一部分。

白话讲清

关卡0 里你一句话一句话地指挥 AI，这在小项目里够用；从本关起项目会连续做一周，AI 每次新会话都会"失忆"。解决办法不是重复唠叨，而是把该说清的话写进项目里，让它每次开工先读。这就是三件套：

  1. 任务卡：这次要做什么、验收条件是什么、不许动什么。（每个任务一张）
  2. AGENTS.md：项目常识——怎么运行、怎么测试、有哪些铁规矩。（一个项目一份）
  3. 验收条件先行：动手前先写"怎样算做完"，做完后逐条对照。

这套做法在行业里叫 Harness / Context Engineering。名字不重要，重要的是：从"聊天式编程"升级为"下达可验收的工作指令"。 这是你和 90% 只会聊天的人拉开差距的地方。

跟我做

  1. 新建项目文件夹 ai-todo-extractor（选 B/C 的自行改名），用搭档打开。
  2. 让搭档创建脚手架（先别写功能）：
初始化一个最简单的 Next.js + TypeScript 项目（用官方默认配置），
然后创建 AGENTS.md，内容包括：
- 项目一句话说明：把会议纪要转成结构化行动清单的自用工具
- 常用命令：安装依赖、启动开发服务、构建
- 铁规矩：1) 每完成一个任务先给我看修改计划和 Diff 再继续；
  2) 任何密钥只放在 .env.local，绝不写进代码，.gitignore 必须排除它；
  3) 每个任务完成后提交一次 git，提交信息用中文写清楚做了什么
完成后教我启动开发服务并在浏览器打开。
  1. 首次运行成功后，做第一次 git 提交（让搭档带你做）。
  2. 从军火库复制《任务卡模板》（AR-1），填出你的第一张任务卡备用。

验收

  • npm run dev（或等价命令）能启动，浏览器打开 localhost 看到默认页
  • AGENTS.md 存在且包含三条铁规矩
  • .gitignore 里有 .env*；已完成首次提交

常见坑

  • Node 版本报错：把报错原样发给搭档，让它给出你系统对应的升级步骤。
  • 端口被占用：词典查"端口"，或直接问搭档"3000 端口被占用怎么办"。
本节完成标准

不是“读完了”，而是证据已经产生。

项目可运行、规则文件存在、首个 Git 提交完成。
