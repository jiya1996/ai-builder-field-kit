S03

AI-Native 开发工作流

怎样让 Coding Agent 持续交付，而不是不断制造不可控修改？

本阶段要做的东西用同一套受控循环完成三个小功能，并成功回滚一次错误修改。
理论学习
4–5 小时
实战周期
2–3 天
输入什么

一页产品规格、可运行产品壳和 Git 仓库。

输出什么

项目规则、任务卡、小步提交、测试记录和可恢复的 Agent 协作循环。

学会什么

把 Spec 拆成受控任务，用 Diff、测试和证据判断是否完成。

KNOWLEDGE

不是记名词，而是理解系统因果。

本阶段只学习马上会在项目中使用和验证的知识。

项目上下文README / AGENTSPlan / TaskScopeDiff测试Git 快照QASkill / HookAgent Loop
01

Agent 不知道你脑中的项目

它只能根据当前上下文行动。README 说明项目，AGENTS 约束工作方式，任务卡定义本次边界；缺少这些信息，模型会用自己的假设填空。

02

Tool Call 不等于任务完成

模型提出修改只是调用意图；工具执行后还需要检查 Diff、运行程序和验证结果。只有可观察证据通过，才能称为完成。

03

小步提交是一种风险控制

把任务缩小到可审查、可测试、可回滚的范围。每个稳定状态形成 Git 快照，失败时回到最后稳定版本，而不是继续在坏状态上堆补丁。

1.1开工三件套第 1 天展开正文
输入

已确定的工具选题、目标用户、核心输入输出，以及可用的本地开发环境。

动手做

初始化 Next.js 项目，写入协作铁规矩。

完成证据

项目可运行、规则文件存在、首个 Git 提交完成。

白话讲清

关卡0 里你一句话一句话地指挥 AI，这在小项目里够用；从本关起项目会连续做一周，AI 每次新会话都会"失忆"。解决办法不是重复唠叨，而是把该说清的话写进项目里，让它每次开工先读。这就是三件套：

  1. 任务卡：这次要做什么、验收条件是什么、不许动什么。（每个任务一张）
  2. AGENTS.md：项目常识——怎么运行、怎么测试、有哪些铁规矩。（一个项目一份）
  3. 验收条件先行：动手前先写"怎样算做完"，做完后逐条对照。

这套做法在行业里叫 Harness / Context Engineering。名字不重要，重要的是：从"聊天式编程"升级为"下达可验收的工作指令"。 这是你和 90% 只会聊天的人拉开差距的地方。

跟我做

  1. 新建项目文件夹 ai-todo-extractor（选 B/C 的自行改名），用搭档打开。
  2. 让搭档创建脚手架（先别写功能）：
初始化一个最简单的 Next.js + TypeScript 项目（用官方默认配置），
然后创建 AGENTS.md，内容包括：
- 项目一句话说明：把会议纪要转成结构化行动清单的自用工具
- 常用命令：安装依赖、启动开发服务、构建
- 铁规矩：1) 每完成一个任务先给我看修改计划和 Diff 再继续；
  2) 任何密钥只放在 .env.local，绝不写进代码，.gitignore 必须排除它；
  3) 每个任务完成后提交一次 git，提交信息用中文写清楚做了什么
完成后教我启动开发服务并在浏览器打开。
  1. 首次运行成功后，做第一次 git 提交（让搭档带你做）。
  2. 从军火库复制《任务卡模板》（AR-1），填出你的第一张任务卡备用。

验收

  • npm run dev（或等价命令）能启动，浏览器打开 localhost 看到默认页
  • AGENTS.md 存在且包含三条铁规矩
  • .gitignore 里有 .env*；已完成首次提交

常见坑

  • Node 版本报错：把报错原样发给搭档，让它给出你系统对应的升级步骤。
  • 端口被占用：词典查"端口"，或直接问搭档"3000 端口被占用怎么办"。
1.2Codex 协作小循环 + Git 后悔药第 1–2 天展开正文
输入

可运行的项目、首个 Git 快照和一张足够小且可验收的页面任务卡。

动手做

完成一个真实页面任务，并亲手回滚一次乱码提交。

完成证据

一条完整协作记录 + 一次成功回滚。

白话讲清

和 Coding Agent 合作的正确节奏不是"一句话生成整个项目"，而是小循环：

阅读现状 → 明确目标 → 它提出计划 → 你确认 → 小步实现
→ 看 Diff（它改了哪些文件哪些行）→ 运行验证 → 人工验收 → git 提交记录状态

一次循环只做一个可验证的任务。为什么？大任务出错时你不知道错在哪一步；小任务出错，回滚成本是几分钟。

Git 在循环里的位置：每次让 AI 动手前，确保上一个稳定状态已提交。 这样任何一步搞砸，一条命令回到安全点。

跟我做（用一个真实小任务练习整个循环）

任务卡示例（发给搭档）：

【任务】给首页做一个标题区
【验收条件】
1. 页面顶部显示产品名"纪要→清单"和一句副标题
2. 手机宽度下不换行错乱
【范围】只允许修改首页文件和全局样式；不要引入任何新依赖
【流程】先告诉我你的修改计划（涉及哪些文件），我确认后再动手；
完成后展示 Diff 摘要，等我在浏览器确认，再提交 git。

跑完整个循环后，做一次回滚演习：

请故意把首页标题改成乱码并提交，然后教我用 git 命令查看提交历史，
并把项目回退到上一个提交。我要亲手输入回退命令。

验收

  • 完整走过一次"计划→确认→实现→Diff→验证→提交"循环
  • 亲手执行过一次回滚，页面恢复正常
  • 能说出：为什么让 AI 动手前要先提交？
学完必须掌握
  • 能写出有边界的任务卡
  • 能读 Diff 判断修改范围
  • 能区分 Agent 声称完成和证据证明完成
理解检查

Agent 回答“已经修复”后，你至少需要检查哪四类证据？
