S01

产品问题与 MVP

为什么很多产品不是做不出来，而是从一开始就做错了问题？

本阶段要做的东西把一个模糊想法收敛成可以在一周内验证的产品任务。
理论学习
2–3 小时
实战周期
1 天
输入什么

一个你反复遇到的问题、现有解决办法和至少一位潜在用户。

输出什么

一页 Product Spec、核心流程、Non-goal 和可验收的 MVP 范围。

学会什么

判断产品为什么做、第一版做什么和不做什么。

KNOWLEDGE

不是记名词，而是理解系统因果。

本阶段只学习马上会在项目中使用和验证的知识。

用户与场景问题证据替代方案核心任务MVPNon-goalProduct Spec验收标准Backlog
01

需求不是一句愿望

“做一个 AI 助手”没有用户、场景和可观察结果。有效问题必须说明谁在什么情况下，正在用什么笨办法，付出了什么代价。

02

MVP 是最小验证，不是残缺产品

第一版只保留验证核心假设所需的完整流程。它可以功能少，但用户必须能从输入走到结果，团队也必须能判断假设是否成立。

03

Non-goal 是保护交付的边界

把暂时不做的登录、支付、移动端或多 Agent 明确写出来，能阻止 Agent 和团队在实现过程中不断扩张范围。

1.0本关地图与三选一选题30 分钟展开正文
输入

最近一周反复处理过的纪要、文案或长文，以及你真实想节省的一段时间。

动手做

从纪要清单、文案打磨、三层摘要中选择一个。

完成证据

写下一周内的真实使用场景与完成条件。

这关杀死哪个焦虑

"做不出"。 上一关你证明了自己能做出网页；这一关你要证明：能和 AI 搭档一起，把一个带真实 AI 能力的功能做完并验收。"做完"从此有客观定义：两张验收单，逐条有证据。

三选一题库（选一个你自己每天真会用的）

选项一句话输入AI 做什么输出
A. 会议纪要转行动清单粘贴会议记录/语音转写，一键变成待办大段文字提取任务、负责人、截止时间结构化清单，可复制
B. 文案打磨器把一段草稿改成 3 种风格的成稿一段草稿 + 目标平台改写、控制语气与长度3 个候选版本并排
C. 长文三层摘要卡读不完的文章变成"30秒/3分钟/追问"三层卡片粘贴全文分层摘要 + 金句 + 3 个追问一张摘要卡

三个选项的工程结构完全相同：一个输入框 + 一次服务端模型调用 + 结构化输出展示。教学以 A 为例逐步演示；B 和 C 只是提示词和展示不同，手册末尾附差异对照。选哪个的唯一标准：你下周真的会用哪个？ 自用是本关的隐藏 Boss——工具做完后连续自用 5 天打卡。

本关技术地图（只引入三个新东西）

  1. 本地开发服务：这次的项目要"跑起来"才能看（不再是双击 HTML）。
  2. 服务端：一段跑在"后台"的代码，替你保管密钥、调用模型。
  3. 模型 API：付费按量调用大模型的接口。
2.0黄金项目与本关地图30 分钟展开正文
输入

已完成关卡 1 的 AI 小工具，以及至少 3 位愿意试用产品的真实联系人。

动手做

选择灵感罐头或同构变体，并确认 3 位种子用户。

完成证据

产品方向、核心流程与用户名单。

这关杀死哪个焦虑

“不敢上线”。 很多学习路径只讲“把东西做出来”，本关进一步训练你判断“这个东西敢不敢给别人用”。本关的每一节都在为最后的 Boss 战铺路——通关那天，你不是"上线了"，而是**"验过了才上线"**。

黄金项目：「灵感罐头」

一句话：一个多用户的 AI 收藏本——用户注册登录，随手存下文字灵感、链接、图片，AI 自动打标签和写摘要，之后可按标签浏览、按关键词找回。

为什么选它？因为它用最小的体积，恰好覆盖一个"真产品"的全部器官：

器官在灵感罐头里
登录与身份注册 / 登录 / 退出 / 受保护页面
数据库 CRUD灵感的增、查、改、删
多用户数据隔离你只能看到你自己的罐头（RLS + 越权测试）
文件图片灵感上传到对象存储
一项真实 AI 能力自动标签 + 一句话摘要
上线Production 环境 + 环境变量 + 域名
运营日志、反馈入口、成本、备份、回滚

两个换皮变体（结构 100% 相同，教学跟主线走即可）：B.「打卡圈」（存的是每日打卡，AI 写每周总结）；C.「反馈墙」（别人给你的产品提反馈，AI 自动归类）。手册末尾附差异对照。

2.1轻量需求与一页规格第 1 天展开正文
输入

选定的产品方向、3 位种子用户和一条必须跑通的核心使用流程。

动手做

填写 PRODUCT.md，并明确至少 3 个不做项。

完成证据

一页产品规格 + 3 个真实用户名单。

白话讲清

关卡4 你会学完整的需求发现方法；本关只用轻量版，回答三个问题就开工：

  1. 给谁用？ 写出 3 个真名（你能拉来注册的真人：同事、朋友、社群同学）。
  2. 一条核心流程是什么？ 灵感罐头的答案：登录 → 存一条灵感 → AI 打好标签 → 之后能找回来。其余全部砍掉：不做分享、不做协作、不做移动 App。
  3. 怎样算成了？ 3 个真人注册、每人存过 ≥3 条、至少 1 人说出一条真实反馈。

跟我做

从军火库复制《一页产品规格模板》（AR-3），10 分钟填完，放进项目 docs/PRODUCT.md。重点填：目标用户（3 个真名）、核心流程一句话、页面清单（登录页/列表页/详情页 3 个足够）、数据对象（"灵感"有哪些字段）、明确不做清单、完成条件。

验收

  • PRODUCT.md 存在，且"明确不做"里至少砍掉了 3 个你很想做的功能
  • 3 个真名已写下（后面 Boss 战要请他们出场）

前三关的项目证据、你真实经历过的问题，以及愿意自主决策的两周时间。

动手做

确认要独立做一个来自真实问题的产品。

个人选题候选池与证据缺口。

这关杀死哪个焦虑

"白学了"的后一半。 demo 谁都有，证据才稀缺。本关结束时你手里有三样东西：一个自己发现的问题被你解决并上线的作品；一页任何面试官 3 分钟能看懂的案例页；一套按 STAR 结构准备好的面试叙事。求职用它，接单用它，做自己的产品也从它开始。

本关和前面最大的不同

没有任务卡喂到嘴边。 我们只给方法、模板和评审。你会第一次完整体验一个 AI Builder 的真实工作循环：发现 → 定义 → 交付 → 验证 → 讲述。

4.1完整 Discovery第 1–3 天展开正文
输入

3–5 个候选问题、潜在目标用户联系方式和已有的行为或请求线索。

动手做

完成访谈、观察、落地页或手工服务中的至少 2 种验证。

完成证据

DISCOVERY.md + 立项或换题结论。

关卡2 用的是轻量需求（三个真名 + 一条流程）；现在学全量方法。

选题的三个来源（按证据强度排序）

  1. 你自己反复付出代价的麻烦（最强：你就是用户，样本量 1 但深度 100%）。
  2. 你能直接接触的一小群人的麻烦（同事、社群、某个垂直圈子——能访谈到 5 个人的圈子才算"能接触"）。
  3. 网上看来的"好点子"（最弱，默认淘汰，除非你能把它转化成前两类）。

四种验证动作（至少做两种，留证据）

动作怎么做合格证据
访谈找 5 个目标用户，问"上次遇到这个麻烦是什么时候、你当时怎么解决的、为此花过什么代价"——问过去的事实，不问"你会不会用"5 份访谈记录，≥3 人近一个月真实遇到
观察潜伏在目标人群的群/论坛一周，记录相关抱怨≥10 条原话截图
落地页一晚上做个介绍页（你已具备此能力）投到目标圈子访问量与留资数
手工服务不写代码，先人肉帮 2 个人解决一次这个问题2 次服务记录与对方反馈

立项门槛（过不了就换题，换题不丢人）

  • 能写出：谁，在什么场景，现在用什么笨办法，付出什么代价
  • ≥2 种验证动作的证据在手
  • 一条核心流程能在你的能力半径内 2 周做完（对照关卡2/3 的复杂度自估；AI 能力限一项）

产出：docs/DISCOVERY.md（问题验证记录，模板见军火库 AR-3 附）。

4.2独立规格、架构与开工评审第 3–4 天展开正文
输入

通过 Discovery 的问题、用户证据、核心任务和已知约束。

动手做

提交一页规格和两张架构图，接受开工评审。

完成证据

规格、架构、风险与不做清单通过评审。

自己完成三份文档（全部用你 Kit 里的模板）：一页产品规格、结构图 + 信任边界图、里程碑计划（2 周切成 4 个里程碑，每个有可验证产物）。

开工评审（社群机制）：把三份文档发到评审频道，至少获得 1 位同学 + 1 位教练的评审通过。评审只问四个问题：问题证据够硬吗？范围砍得够狠吗？架构里红线画对了吗？里程碑可验证吗？——通过后开工，防止两周走偏。

  • 三份文档 + 评审通过记录
学完必须掌握
  • 能把功能想法改写成问题证据
  • 能画出一条端到端核心流程
  • 能写出明确的不做项和验收条件
