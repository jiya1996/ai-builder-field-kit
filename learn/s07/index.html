S07

产品载体与系统扩展

什么时候应该扩展到移动端、本地模型、多 Agent 或长期运行系统？

本阶段要做的东西为现有产品选择一个真实扩展，完成小规模对照实验后决定采用或拒绝。
理论学习
5–7 小时
实战周期
3–5 天
输入什么

已经验证的产品、真实约束和当前系统瓶颈。

输出什么

一份扩展决策记录和一个经过验证的最小技术实验。

学会什么

基于场景、隐私、成本、延迟和协作瓶颈接受或拒绝扩展。

KNOWLEDGE

不是记名词，而是理解系统因果。

本阶段只学习马上会在项目中使用和验证的知识。

01

载体由使用场景决定

需要相机、定位、推送或离线能力时，移动端才形成硬约束。只因为“想做 App”就迁移技术栈，会增加发布与维护成本。

02

本地模型是一组取舍

它可能改善隐私和离线能力，但会引入设备算力、模型体积、更新和质量差异。Model Card 用来理解训练范围、能力和限制。

03

多 Agent 解决组织问题，不自动提升智能

只有角色需要不同工具、权限或并行上下文时才值得拆分。否则通信、状态同步和错误归因会比单 Agent 更复杂。

输入

已验证需求的线上产品、测试支付账号和明确的商品、价格与额度规则。

动手做

在测试模式跑通支付或先做手工付费验证。

完成证据

商业闭环验收单；本节不阻塞主线通关。

不是必修。想跑通商业闭环的做这里：

  • 邮件通知（出海向）：接入 Resend 类邮件 API，注册欢迎信 + 反馈自动回执。
  • 支付：出海用 Stripe Checkout（测试模式跑通"点按钮→托管支付页→成功页"，重点理解支付结果以服务端验证的 Webhook 为准，不能信前端跳转）；国内个人开发者无微信支付商户资质时，可评估聚合方案（虎皮椒、Z-Pay 等，接入前必须自行核实资质、费率与合规风险），或先用"手动开通会员"的人肉闭环验证付费意愿——验证意愿不需要自动化。
  • 简单额度：给 enrich 加每日免费次数 + 付费解锁的字段与判断。
