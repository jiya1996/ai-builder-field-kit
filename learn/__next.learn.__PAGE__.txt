3:Ta9d,### 为什么要解剖

接下来你要花真金白银调用模型。花钱之前，必须看穿这笔钱买的是什么、藏在哪些环节。**这一节没有代码任务，但决定你以后所有 AI 功能的质量和成本。**

### 一次调用的完整解剖图

```text
你的服务端代码
   │  组装一次请求（花钱从这里开始计量）
   ▼
┌─ 请求包 ────────────────────────────────┐
│ ① 模型名：决定能力/速度/单价               │
│ ② 消息列表：                             │
│    system 指令  ← 你产品的"岗位说明书"      │
│    user 内容    ← 用户这次贴进来的纪要      │
│   （多轮对话时还有历史消息，本关用不到）       │
│ ③ 参数：温度(稳定↔发散)、最大输出长度        │
│ ④ 密钥：证明"扣我的账"——所以绝不能泄露      │
└──────────────┬─────────────────────────┘
               ▼  模型服务商
┌─ 响应包 ────────────────────────────────┐
│ 模型输出的文字（或结构化 JSON）             │
│ 用量：输入 token 数 + 输出 token 数 → 费用   │
└──────────────┬─────────────────────────┘
               ▼
你的服务端解析输出 → 返回给页面展示
```

### 五个必须刻进脑子的结论

1. **Token 是计费单位**，输入和输出都算钱。粘贴 1 万字纪要 ≈ 上万输入 token。所以"限制输入长度"不是抠门，是产品设计。
2. **system 指令是你产品的灵魂**。同一个模型，A/B/C 三个工具的差别几乎全在 system 指令里。
3. **温度不是"聪明度"**。提取任务这种要稳定的场景用低温度；文案打磨这种要花样的场景可以调高。
4. **模型输出天生不稳定**。要让程序消费结果（比如渲染成清单），必须要求**结构化输出（JSON）并在代码里校验**，不能指望它"每次都乖"。
5. **密钥 = 你的钱包**。出现在浏览器代码、GitHub 仓库、截图里的任何一处，都等于把钱包丢在路上。这就是为什么调用必须发生在**服务端**。

四个新词，一句话版（详版见词典）：

- **表**：Excel 的一张 sheet。我们建一张 `ideas` 表。
- **行/字段**：一行=一条灵感；字段=每条灵感记录的属性。
- **主键 id**：每行的身份证号。
- **CRUD**：增（Create）查（Read）改（Update）删（Delete），一切管理型产品的四个基本动作。

`ideas` 表设计（先照抄，2.6 会解释 user_id 为什么是命根子）：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | uuid 主键 | 自动生成 |
| user_id | uuid | 这条灵感属于谁（关联登录用户） |
| content | text | 文字内容或链接 |
| kind | text | text / link / image |
| image_path | text 可空 | 图片在 Storage 里的路径 |
| tags | text[] | AI 打的标签 |
| summary | text 可空 | AI 一句话摘要 |
| created_at | timestamptz | 创建时间 |
