01

语言、框架和工具不是同一类东西

JavaScript 是语言；React 是用 JavaScript 构建界面的库；Next.js 是组织前端、服务端和路由的框架；VS Code、Codex 和 Git 是帮助开发的工具。

02

前端负责交互，后端负责可信执行

浏览器里的代码可以被用户查看和修改，因此密钥、权限判断和可信数据写入必须放在服务端。前后端通过 HTTP API 交换 JSON。

03

认证回答你是谁，授权回答你能做什么

登录成功只证明身份。数据库仍需根据用户身份限制每一行数据；RLS 把这种规则放到数据库层，避免只靠页面隐藏按钮。

1.3先做不带 AI 的壳第 2–3 天展开正文
输入

选题的输入样例、预期输出样例，以及已经定义好的正常、加载、失败状态。

动手做

先用假数据完成输入、按钮、结果与模拟失败。

完成证据

三种状态均已亲测，移动端可用。

白话讲清

先把"壳"做完——输入、按钮、结果区，以及三种状态：

  • 空状态：还没输入时页面显示什么（引导语 + 示例按钮）。
  • 加载状态：点了按钮、结果没回来时显示什么（转圈 + 禁用按钮防连点）。
  • 错误状态：失败了显示什么（人话提示 + 重试按钮）。

为什么先做壳？因为AI 能力是不确定的，壳是确定的。壳先验收通过，之后出问题就能立刻判断：是壳的问题还是 AI 的问题。这是排错的"分层隔离"思想，急救室会反复用到。

跟我做

一张任务卡搞定（以 A 为例）：

【任务】完成工具的前端壳（暂时不接 AI，用假数据）
【验收条件】
1. 一个多行文本输入框（占位提示：粘贴会议纪要...）+ 一个"提取行动清单"按钮
2. 空状态：显示使用说明和一个"填入示例纪要"按钮
3. 点击按钮后进入加载状态：按钮禁用并显示"提取中..."，2 秒后展示一份写死的假清单
   （3 条待办，每条含 任务/负责人/截止时间 三个字段）
4. 有一个"模拟失败"开关：打开时点击按钮 2 秒后显示错误提示和"重试"按钮
5. 手机宽度可正常使用
【范围】不接任何真实 API，不引入 UI 组件库
【流程】同 AGENTS.md 铁规矩

逐条验收，提交。

验收

  • 空 / 加载 / 错误三状态全部亲眼验证过（错误态用开关触发）
  • 假数据以"任务/负责人/截止时间"结构展示
  • git 已提交
2.2架构透视与信任边界第 1–2 天展开正文
输入

已经评审的一页产品规格，以及核心流程中会经过的数据和外部服务。

动手做

亲手画结构图和信任边界图。

完成证据

两张架构图，能指出密钥与权限必须放在哪里。

白话讲清

这一节回答"系统由什么组成、数据怎么流、为什么这样组合"。你要亲手画两张图（手画拍照即可，不要求工具）：

图一：结构图。 把 2.0 的地图抄一遍，但每个方框里写上你自己项目的具体内容（页面叫什么、表叫什么、接口叫什么）。

图二：信任边界图。 用一条红线把系统切成两半：

        【不可信区：用户的浏览器】
  页面代码、用户输入 ← 这里的一切都可能被查看、被伪造
──────────────红线（信任边界）──────────────
        【可信区：你的服务端 + Supabase】
  密钥、身份校验、权限判断、数据库规则 ← 只能放在这里

三条推论，本关后面全部会用到：

  1. 前端"隐藏按钮"不是安全措施——按钮藏得住，接口藏不住。
  2. 一切校验（是不是本人、能不能看这条数据）必须发生在红线以下。
  3. 密钥出现在红线以上的任何位置 = 泄露。

默认技术栈与取舍（照抄，不纠结）

第一版默认栈：Next.js + TypeScript + Supabase + Vercel。理由只有三条：一体化（前端后端一个项目）、免运维（不用买服务器）、生态大（AI 搭档最熟悉，报错资料最多）。其他栈不是不好，是同时学两条路线必死。等你通了关卡3，换栈是一周的事。

验收

  • 两张图画完，拍照存入 docs/
  • 能指着图回答：用户点"保存灵感"后，数据经过哪几站？密钥住在哪一站？
2.3搭页面与路由骨架第 2–3 天展开正文
输入

产品规格、结构图，以及登录、列表、新建三个页面的纸面流程。

动手做

完成三页跳转、空状态、加载状态与移动端布局。

完成证据

可浏览的产品壳 + 对应 Git 提交。

跟我做

沿用关卡1 的三件套开工：初始化项目、写 AGENTS.md（把 2.1 的 PRODUCT.md 和铁规矩接上）、首个提交。然后一张任务卡：

【任务】完成灵感罐头的页面骨架（先不接数据库和登录，全部用写死的假数据）
【页面清单】
1. /login 登录页（表单先摆着，不校验）
2. / 罐头列表页：网格卡片展示 6 条假灵感（字段：内容摘录、类型 文字/链接/图片、
   标签、创建时间），顶部有"新建灵感"按钮和标签筛选条
3. /new 新建页：一个大输入框 + 图片选择占位 + 保存按钮（点击后跳回列表）
【验收条件】三个页面能互相跳转；列表页手机宽度单列显示；空/加载状态占位齐全
【范围】不接 Supabase，不引入大型 UI 库

逐条验收，提交。壳先行的理由和关卡1 相同：AI、数据库、登录接进来之前，壳必须是确定可用的。

验收

  • 三页可跳转，假数据显示正常，手机宽度可用
  • git 已提交（本关起不再提醒，默认每个任务卡完成即提交）
学完必须掌握

  • 能画出一次按钮点击的数据流
  • 能解释认证、授权与 RLS 的边界
