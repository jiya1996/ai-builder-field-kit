白话讲清

这里复用关卡1 的全部功力（服务端调用、结构化输出、校验兜底），新增两个真产品才有的问题：

  1. 成本会随用户增长：自用工具花的是你的小钱；多用户产品花的可能是大钱。
  2. 防盗刷：接口公开在互联网上，必须限制"谁、多频繁、花多少"。

跟我做

【任务】保存灵感时自动生成标签和摘要
【实现】
1. 服务端接口 /api/enrich：输入灵感文字，调用模型返回 JSON
   {tags: 最多3个中文标签, summary: 不超过30字的一句话摘要}；
   system 指令要求只依据输入内容、禁止编造、只输出 JSON
2. 新建流程：先保存灵感（保证不丢），再异步调用 enrich 回填 tags/summary；
   AI 失败不影响保存，卡片显示"标签生成失败·重试"
3. 防护三件套：a) 单用户每分钟最多 5 次 enrich（超出返回明确提示）；
   b) 输入截断到 2000 字再送模型；c) 未登录调用 /api/enrich 直接拒绝
4. 在服务端日志打印每次调用的 token 用量
【验收】存一条灵感几秒后标签浮现；AI 挂了灵感也不丢；
       连续快速保存第 6 条时出现频率限制提示；退出登录后用工具直调接口被拒

再做一次成本推演（写进 docs/COST.md）：单次 enrich 成本 × 预估每用户每天条数 × 用户数 = 日成本。用你的真实 token 数据算。"看得见成本"是 AI Builder 和"接了个 API 的人"的区别。

验收

  • 验收四连全部通过
  • COST.md 有你自己的成本推演数字
