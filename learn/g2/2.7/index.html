不要只看

代码块、提示词和检查框都是本节任务的一部分。

白话讲清

图片不进数据库表（表存文字），进对象存储（Storage）；表里只存图片的路径。就像衣帽间存大衣，你手里只拿号码牌。

上传功能的完整责任清单：类型限制（只收图片）、大小限制（比如 5MB）、权限（谁能看：本关设为"仅本人"）、失败处理（超限时人话提示）、删除（删灵感时连图片一起删，不留垃圾）。

跟我做

【任务】支持图片灵感
【实现】
1. 在 Supabase Storage 创建 bucket：ideas-images，访问策略设为需登录、按用户目录隔离
   （路径规则：{user_id}/{文件名}），并解释这条策略
2. 新建页支持选择图片：限 jpg/png/webp，≤5MB，超限前端直接提示不上传
3. 上传成功后把路径写入 image_path，kind 设为 image；列表卡片能显示缩略图
4. 删除图片类灵感时，先删 Storage 文件再删表行；任一步失败要提示
【验收】传一张正常图 √ / 传一个 PDF 被拒 √ / 传超大图被拒 √ / 删除后 Storage 里文件消失 √
       / 账号 B 拿到 A 的图片地址也打不开（隔离生效）

验收

  • 上表五个 √ 全部亲测
  • 能回答：为什么表里只存路径不存图片本体？
