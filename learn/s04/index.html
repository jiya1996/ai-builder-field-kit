01

真实产品的核心是状态

静态页面只展示文件；真实产品要为不同用户保存、读取和修改状态。数据库结构决定系统记住什么，Migration 决定结构如何安全变化。

02

权限必须在可信边界内执行

页面隐藏按钮不能阻止攻击者直接请求接口。服务端和数据库必须验证身份、资源归属和允许的动作。

03

上线不是复制文件

Preview 用于验证候选版本，Production 面向真实用户。环境变量、数据库迁移、日志、备份与回滚决定系统出错后能否恢复。

2.4数据库、字段与 CRUD第 3–5 天展开正文
输入

可浏览的产品壳、ideas 数据字段清单和可用的数据库项目。

动手做

建立 ideas 表，接通新增、读取、删除和刷新持久化。

完成证据

数据库真实数据 + CRUD 验收记录。

白话讲清

四个新词，一句话版（详版见词典）：

  • 表：Excel 的一张 sheet。我们建一张 ideas 表。
  • 行/字段：一行=一条灵感；字段=每条灵感记录的属性。
  • 主键 id：每行的身份证号。
  • CRUD：增（Create）查（Read）改（Update）删（Delete），一切管理型产品的四个基本动作。

ideas 表设计（先照抄，2.6 会解释 user_id 为什么是命根子）：

字段类型说明
iduuid 主键自动生成
user_iduuid这条灵感属于谁（关联登录用户）
contenttext文字内容或链接
kindtexttext / link / image
image_pathtext 可空图片在 Storage 里的路径
tagstext[]AI 打的标签
summarytext 可空AI 一句话摘要
created_attimestamptz创建时间

跟我做

  1. 注册 Supabase，创建项目（区域就近选），拿到项目 URL 和 anon 公钥，放进 .env.local（让搭档带你做，规矩同关卡1）。
  2. 建表任务卡：
【任务】在 Supabase 创建 ideas 表并接通读写
【实现】
1. 按我给的字段设计生成建表 SQL，先解释每一行 SQL 的意思，我确认后再执行
2. 先开启 RLS 但临时添加"仅登录用户可读写自己数据"的占位策略——如果当前
   还没接登录，明确告诉我现在用什么临时策略、上线前必须改成什么（记入 docs/TODO.md）
3. 列表页改为从数据库读取；新建页真实写入；卡片上加删除按钮（删除必须二次确认）
【验收】新建一条 → 列表立刻出现 → 刷新还在 → 删除后消失；Supabase 后台能看到对应行
  1. 亲手在 Supabase 的表编辑器里手动插入一行数据，刷新你的页面看它出现——建立"数据在表里，不在页面里"的体感（词典认知卡 #6）。

验收

  • 增查删全部走通，且"刷新后还在"（这是数据库与假数据的分水岭）
  • 能回答：删除为什么必须二次确认？（破坏性操作不可逆）
  • docs/TODO.md 里记下了"上线前收紧 RLS"事项

常见坑

  • 读不到数据且报权限类错误：多半是 RLS 策略问题，正常——2.6 专门治它。先按搭档指引用临时策略跑通，但绝不允许"彻底关闭 RLS"图省事，那等于把家门拆了。
2.5注册、登录与受保护页面第 5–7 天展开正文
输入

已经接通 CRUD 的应用、邮箱登录方案和需要保护的页面清单。

动手做

接入邮箱注册登录，未登录访问受保护页必须被拦截。

完成证据

注册—退出—登录闭环 + 地址栏直入拦截测试。

白话讲清

两个词必须分清（词典认知卡 #7）：

  • 认证：你是谁。（登录解决的问题）
  • 授权：你能干什么。（RLS 和权限解决的问题，下一节）

登录成功 ≠ 拥有一切权限。本节只解决"你是谁"。

跟我做

任务卡：

【任务】用 Supabase Auth 接入邮箱注册/登录/退出，并保护页面
【实现】
1. /login 页支持注册与登录（邮箱+密码），错误时给人话提示（密码错误/邮箱已注册等）
2. 登录成功跳转列表页；导航栏显示当前邮箱和"退出"按钮
3. 未登录访问 / 和 /new 时自动跳到 /login（服务端校验，不是前端藏按钮）
4. 新建灵感时把当前用户 id 写入 user_id 字段
【验收】注册→退出→登录闭环可用；未登录直接输入列表页网址会被弹回登录页

完成后做一个红线实验：退出登录，直接在浏览器地址栏输入列表页网址。如果能看到内容，说明保护做在了前端（红线以上），退回去让搭档改为服务端校验。

验收

  • 注册/登录/退出闭环 + 未登录强制跳转（亲测地址栏直入被拦）
  • 新建的灵感在数据库里带上了你的 user_id
2.6RLS 与双账号隔离第 7–9 天展开正文
输入

已接入登录和用户归属字段的数据库，以及两个独立测试账号。

动手做

配置增查改删四条策略，用账号 B 直调接口访问 A。

完成证据

页面与接口层越权均被拒绝的截图。

白话讲清

现在有个致命问题：所有登录用户看到的是同一堆灵感。真产品必须做到"我只能看我的"。

两层防线：

  1. 应用层：查询时按当前 user_id 过滤。（必要，但不够——万一哪天某个接口忘了过滤呢？）
  2. 数据库层 RLS（行级安全）：让数据库亲自把关每一行——"这行的 user_id 不是你？不给看，不给改，不给删。"应用层写错了，RLS 也兜得住。这是本关最重要的安全概念。

RLS 策略读法（示意）：

-- 只允许读自己的行
create policy "read own ideas" on ideas
  for select using (auth.uid() = user_id);
-- 只允许以自己的身份插入
create policy "insert own ideas" on ideas
  for insert with check (auth.uid() = user_id);

using 管"看/改/删已有行时查户口"，with check 管"写入新行时验身份"。改和删同理各写一条。

跟我做

【任务】为 ideas 表配置完整 RLS 策略并替换掉临时策略
【实现】按"用户只能 增/查/改/删 自己的行"生成四条策略 SQL，逐条向我解释
using 和 with check 的含义，我确认后执行；删除 2.4 的临时策略；清空 docs/TODO.md 对应项
【验收】见下方双账号实验

双账号实验（Boss 战预演，现在就做）：

  1. 用另一个邮箱注册第二个账号（浏览器无痕窗口登录）。
  2. 账号 B 的列表页应该是空的——看不到账号 A 的任何灵感。
  3. 进阶：让搭档教你在浏览器控制台里，用账号 B 的身份直接调用查询接口尝试读取 A 的数据——应当返回空或被拒绝。接口层面试过才算数，页面上看不见不算数（红线原理）。

验收

  • 四条 RLS 策略生效，临时策略已删除
  • 双账号实验通过，且做过一次"绕过页面直调接口"的尝试并被拒
  • 能用一句话向朋友解释 RLS 是什么
2.7文件上传与对象存储第 9–11 天展开正文
输入

已完成账号隔离的应用、对象存储空间和图片类型与大小规则。

动手做

完成图片上传、超限拦截、缩略图与删除清理。

完成证据

正常、非法、超大、删除、跨账号五项测试。

白话讲清

图片不进数据库表（表存文字），进对象存储（Storage）；表里只存图片的路径。就像衣帽间存大衣，你手里只拿号码牌。

上传功能的完整责任清单：类型限制（只收图片）、大小限制（比如 5MB）、权限（谁能看：本关设为"仅本人"）、失败处理（超限时人话提示）、删除（删灵感时连图片一起删，不留垃圾）。

跟我做

【任务】支持图片灵感
【实现】
1. 在 Supabase Storage 创建 bucket：ideas-images，访问策略设为需登录、按用户目录隔离
   （路径规则：{user_id}/{文件名}），并解释这条策略
2. 新建页支持选择图片：限 jpg/png/webp，≤5MB，超限前端直接提示不上传
3. 上传成功后把路径写入 image_path，kind 设为 image；列表卡片能显示缩略图
4. 删除图片类灵感时，先删 Storage 文件再删表行；任一步失败要提示
【验收】传一张正常图 √ / 传一个 PDF 被拒 √ / 传超大图被拒 √ / 删除后 Storage 里文件消失 √
       / 账号 B 拿到 A 的图片地址也打不开（隔离生效）

验收

  • 上表五个 √ 全部亲测
  • 能回答：为什么表里只存路径不存图片本体？
2.10上线 Production第 14 天展开正文
输入

通过安全检查的版本、生产环境变量和一个从未注册过的新邮箱。

动手做

构建、配置生产变量、发布并用全新账号走完整流程。

完成证据

手机流量下的 Production 全流程记录。

白话讲清

三个环境从此分开：本地（你的电脑，随便折腾）、预览（每次改动的临时试映厅，Vercel 自动生成）、生产 Production（给用户的正式版）。铁律：本地的 .env.local 不会自动进云端——生产环境变量必须在 Vercel 后台单独配置。

跟我做

  1. 部署前本地先跑一次构建（npm run build），把构建错误消灭在本地。
  2. Vercel 导入 GitHub 仓库 → 在项目设置里逐个配置环境变量（Supabase URL/anon key、模型密钥），注明作用于 Production。
  3. 部署完成后，做线上验收：用手机流量，注册一个全新账号，完整走一遍核心流程（注册→存文字灵感→存图片灵感→看到 AI 标签→删除→退出）。
  4. 可选：绑定自定义域名（几十元/年，搭档带你配 DNS）。

验收

  • 线上核心流程手机亲测通过
  • 浏览器查看线上页面源码，搜不到任何密钥
  • Supabase 后台能看到线上新账号产生的真实数据
学完必须掌握
  • 能画出多用户产品架构图
  • 能解释数据隔离和信任边界
  • 能区分 Preview、Production、备份和回滚
